# Стена славы, именная рыба, Старый Лей и честный турнир

Дата: 2026-10-07. Модуль: `mods/aquatech-ui` (пакет `net.aquatech.ui`). Коммитов и деплоя в этом плане нет.

## Что выяснено до начала (проверено по коду и байткоду, не предположения)

1. Starcatcher 2.3.19 пишет вес в предмет в NBT-ключ `starcatcher:caught_fish_info` (компонент через NeoBackports,
   имя ключа = `ResourceLocation.toString()`): `{size:int см, weight:int граммы, percentile:float, rarity:string, golden:bool}`.
2. Код проекта ищет ключ `caught_fish_info` без `starcatcher:` (`OceanEventsService:526`, `FishShopConfig:312`), поэтому
   настоящий вес никогда не находится и турнир подставляет случайный `0.3 + rnd*rnd*24` кг, не зависящий от вида.
3. Для всех удочек, кроме `sky`/`boner`, `FishingLootHandler.awardCatch` стирает улов Starcatcher и выдаёт свой лут
   (`FishRosterService.roll` возвращает `new ItemStack(item)` без компонентов): настоящего веса у такого улова нет.
   Ветка `sky`/`boner` оставляет настоящий улов, но `OceanEventsService.onCatch` из неё не вызывается: турнир её не видит.
4. В турнир сейчас попадает любой предмет улова (включая руды): «самая тяжёлая рыба» может быть булыжником.
5. Вес по видам есть: в jar Starcatcher `data/starcatcher/starcatcher/fish/*.json`, поле `size_and_weight`
   (`average_weight_grams`, `deviation_weight_grams`, `average_size_cm`, `deviation_size_cm`). 96 из 97 видов
   из `config/aqualumen/fish_shop.json` покрыты (нет только `starcatcher:missingno`).
6. Цены в `FishShopConfig.priceParts` читают `aquatech_tournament_weight` (кг), который ставился на КОПИЮ предмета (`awarded`), а не на выданный игроку, поэтому в цене никогда не участвовал. Старый случайный вес по выходным убран как мёртвый код; экономика не меняется.
7. Портал хранит турнир как «вес за неделю» (D1: `tournament_entries`). Категорию «по числу уловов» на портал не отправляю.

## Принятые решения (если не нравится, правится одной константой)

- Турнир: две категории. **«Тяжеловес»** (самая тяжёлая рыба, как сейчас: 2500/1000/500 монет, ключи flora/steam/smeltery,
  бустеры) и **«Рекордсмен улова»** (больше всего уловов за выходные: 1250/500/250 монет, без ключей и бустеров).
  Один игрок может взять приз в обеих. Вес считается только для рыбы (есть данные вида), руды не участвуют.
  Уловом считается каждый успешный улов (`onCatch`, а также ветка `sky`/`boner`).
- Вес: настоящий компонент Starcatcher, если он есть; иначе ролл по распределению вида и запись компонента в предмет
  (тогда штатный тултип Starcatcher покажет вес и размер). Строка старого веса в тултипе скрывается, если есть настоящий.
- Стена славы: рекорд по каждому виду, по весу в граммах. Первый рекорд вида записывается, только если вес не меньше среднего
  веса вида (иначе первый же улов был бы «рекордом»).

## Фазы (каждая завершается сборкой `./gradlew build` и тестами)

### Фаза 1. Честный вес и турнир
- `tools/gen_fish_weights.py` читает jar Starcatcher, пишет `src/main/resources/data/aquatech_ui/fish_weights.json`.
- `FishWeight` (чистая логика + тонкий слой NBT): `gramsOf(stack)`, `roll(species, random)`, `stamp(stack, random)`,
  `speciesOf(stack)`, нормальное распределение с отсечением, процентиль через CDF.
- `TournamentLogic`: категория по числу уловов (`Count`-записи, `recordCatch`, призы), снимок для портала не меняется.
- `OceanEventsService`: вынести турнир в `recordTournament(player, awarded)`, вызывать из `onCatch` и из ветки `sky`/`boner`.
- `TournamentState` получает `counts`, `pendingCount`; обратная совместимость со старым `aquatech_tournament.json`.
- Тесты: `FishWeightTest`, расширить `TournamentLogicTest`.

### Фаза 2. Именная рыба и данные стены славы
- `FameService` (серверный): `config/aquatech_hall_of_fame.json`, `onFish(player, stack)`, рекорд по виду, анонс в чат,
  штамп предмета (`AquaRecord` тег: владелец, вес, дата; имя и лор «Щука Xieto · 14.2 кг»).
- Чистая логика рекорда вынесена в `FameLogic` (тесты).

### Фаза 3. Табличка славы (блок) и модель
- Блок `fame_plaque` + `FamePlaqueBlockEntity` (вид привязывается ПКМ рыбой оператором или `/aquafame bind`), синхронизация на клиент,
  `FamePlaqueRenderer` рисует предмет рыбы, имя рекордсмена и вес.
- Модель в Blockbench: латунная рамка с подвесом, окошко под рыбу, табличка снизу. Экспорт блок-модели и текстуры в мод.

### Фаза 4. Рыбак-сосед (NPC)
- `FishNeighborEntity` по шаблону `BeeKeeperEntity` (GeckoLib, без ИИ): не торгует и не даёт заданий.
  ПКМ: случайная история из списка (вода, старая рыба, сервер). Реагирует на рекорды стены и на тяжёлый улов рядом.
- Модель, текстура и анимации в Blockbench (сидит на пирсе, удочка, поплавок), экспорт через скрипт по образцу
  `tools/export_bee_keeper.py`.

### Фаза 5. Старый Лей (легендарная рыба-босс)
- Событие: Лей всплывает на неделю один раз; первый, кто его вытащил в зоне события, получает именной предмет и титул.
  Пул ролла остаётся серверным (мимо датапака Starcatcher, т.к. основной путь стирает его улов).
- Модель Лея в Blockbench для витрины и события.
- Детали боя уточняются после того, как будут готовы фазы 1–4 (повторное использование `RhythmHookSession`).
