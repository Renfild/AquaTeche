# Недельный турнир: таблица на сайте, кейс-ключи, архив

Дата: 2026-09-29. Статус: черновик на ревью.

## Цель

Довести существующий недельный турнир по улову до события с витриной: результаты
в реальном времени на портале, кейс-ключи в призах, архив прошлых недель («зал славы»).
Регулярная причина заходить и готовый материал для TikTok (скрины таблицы, «топ-1 недели»).

## Что уже есть (проверено по коду)

- `OceanEventsService`: турнир сб–вс, побеждает самая тяжёлая рыба, призы 2500/1000/500 монет,
  топ-3 в Tab, состояние в `config/aquatech_tournament.json` (`TournamentState`: `week`, `top`).
- Вес рыбы: StarCatcher не пишет вес, мод подставляет случайный `0.3 + r*r*24` и кладёт в NBT-тег
  `aquatech_tournament_weight`.
- Канал сервер -> портал: `POST /api/sync/player`, заголовок `X-AquaTech-Server-Key`,
  секрет `SERVER_SYNC_KEY`, БД D1; ключ на сервере в `config/aquatech_sync_key.json`.
- Ключи кейсов: `player.getPersistentData()` -> `aqualumen_case_keys` -> `{caseId: count}`
  (тот же формат пишет `WelcomeGift`).

## Найденные баги, которые чинит эта работа

1. `weekNumber() = год*100 + dayOfYear/7` не совпадает с границей сб–вс: выходные могут попасть
   на стык, и топ сбросится посреди турнира. Замена: ISO-неделя (`IsoFields`).
2. Призы получает только тот, кто онлайн в момент итогов; вышедший победитель теряет награду.
   Замена: очередь отложенных призов, выдача при входе.

## Решения

- Объём: табло + архив прошлых недель. Очковых сезонов нет.
- Призы за места 1/2/3: монеты 2500/1000/500 (как сейчас) + ключи кейсов `flora` / `steam` / `smeltery`.
- Таблица на сайте: топ-10 недели, одна лучшая рыба на игрока.
- Транспорт: мод шлёт полный снимок состояния (идемпотентно); сайт не может читать Apex,
  поэтому только push с сервера.

## Часть 1. Воркер и БД

Миграция `migrations/0011_tournament.sql`:

- `tournament_weeks(week INTEGER PRIMARY KEY, ends_at TEXT, next_starts_at TEXT NULL, status TEXT)` — `status` in `active|finalized`.
- `tournament_entries(week INTEGER, uuid TEXT, nick TEXT, weight REAL, fish TEXT, PRIMARY KEY(week, uuid))`.
- Рекорд за всё время: `MAX(weight)` по `tournament_entries`, отдельной таблицы нет.
- `week` = `год*100 + ISO-неделя`.

`POST /api/sync/tournament` (`functions/api/sync/tournament.js`):

- Авторизация: `X-AquaTech-Server-Key` == `env.SERVER_SYNC_KEY`, иначе 403 (как в `sync/player.js`).
- Тело: `{week, status, ends_at, next_starts_at?, top:[{uuid, nick, weight, fish}]}`, `top` не длиннее 10; невалидные значения отклоняются. `next_starts_at` (ISO, опционально) нужен странице для отсчёта до следующего турнира, потому что часовой пояс сервера сайту неизвестен.
- Upsert недели и полная замена её записей снимком в одном batch.
- Если неделя уже `finalized`, запрос принимается, но данные не меняются (архив неизменяем).

`GET /api/tournament` (`functions/api/tournament.js`), публичный:

- Текущая (или последняя) неделя: `week`, `status`, `ends_at`, `server_time`, `top` (до 10).
- `?history=N` (N ограничен сверху): победители последних N завершённых недель (тройки),
  рекорд веса за всё время, рейтинг по числу побед.

Оба роута регистрируются в `worker/index.js`. `nick` только для показа, идентификатор — `uuid`.

## Часть 2. Мод (`mods/aquatech-ui`)

- ISO-неделя вместо `weekNumber()`; то же значение уходит на портал.
- `TournamentState`: `top` до 10, `endsAt`, `finalSent`, `pending` (`uuid`, монеты, ключ, неделя, место).
  Хранение остаётся в `config/aquatech_tournament.json`.
- Итоги: места 1/2/3 -> монеты + ключ (`flora`/`steam`/`smeltery`). Онлайн получает сразу,
  офлайн — запись в `pending`, выдача в `PlayerLoggedInEvent`. Ключ пишется по формату `WelcomeGift`.
- Новый `PortalTournamentSync`: отправка снимка в отдельном потоке (игру не блокирует),
  при старте недели, при изменении топа (с ограничением частоты) и при итогах (`status=finalized`).
  Ключ читается из `config/aquatech_sync_key.json`. При неудаче состояние остаётся в файле,
  а `finalSent=false` повторяет отправку итогов при следующем старте сервера.
- Ограничение архитектуры: никаких compile-зависимостей от `aqualumen-ui` и `aquatech-machines`.

## Часть 3. Сайт

- `docs/tournament.html` — ручной HTML в стиле `site.css`; пункт меню в `docs/assets/js/site.js`,
  ссылка из карточки турнира в `docs/events.html`. `tools/generate_site.py` не используется.
- Живая таблица: топ-10, опрос `GET /api/tournament` раз в 30 секунд, таймер до конца
  по `server_time` из ответа, призовая тройка с наградой.
- Вне выходных: итоги прошлой недели и отсчёт до `next_starts_at`.
- Зал славы: победители последних 12 недель, рекорд веса, рейтинг побед.
- Блок «Топ-1 недели» рассчитан на скриншот; OG-мета для превью ссылки.

## Обработка ошибок

- Портал недоступен: игра не страдает, снимок повторится при следующем изменении, итоги — при старте сервера.
- Неверный ключ или БД не подключена: 403 / 503, как у существующих sync-роутов.
- Пустая неделя (никто не поймал рыбу): страница показывает пустое состояние, призы не выдаются.

## Проверка

- Java: `./gradlew build` в `mods/aquatech-ui`. JS: `node --check` для новых файлов и `worker/index.js`.
- Локальный Mohist: снимок уходит и принимается; переход недели не сбрасывает топ посреди выходных;
  отложенный приз выдаётся при входе офлайн-победителя.
- Воркер: проверка `POST`/`GET` на тестовых данных, включая отказ на неверный ключ и игнор
  обновлений завершённой недели.

## Выкатка

Порядок: миграция D1 -> воркер -> мод -> страница. Деплой и миграцию выполняет владелец
(классификатор блокирует прод-операции); перед деплоем мода игра должна быть закрыта.
После выкатки — запись в `IMPLEMENTATION_PLAN.md` и `GUIDEBOOK.md`.

## Вне объёма

Очковые сезоны, кооператив, живой рынок цен, профиль игрока — отдельные задачи.
